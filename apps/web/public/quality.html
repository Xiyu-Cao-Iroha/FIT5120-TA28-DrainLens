Code quality

Every number on this page was measured on 7 September 2026, by running the command named beside it. None is carried forward from an earlier run, and the things that are not green are on the page with the things that are — a quality report showing only passes is not evidence of quality, it is evidence of what was reported.

Release quality checks

Code review

Branch → pull request → written review → merge

  • 70 merged pull requests. Every change to main has been through one — there is no other route.
  • Zero direct pushes to main, enforced by a GitHub ruleset and tested by attempting one. A rule nobody has seen refuse anything is a rule nobody should trust.
  • Feature branches are cut from develop; develop → main is the release. Every PR description says what changed and why, including the defects found while making it.

Automated checks

Three CI jobs, on every pull request

  • check — TypeScript build, then Vitest with coverage thresholds enforced in configuration: 88% overall, 90% for the judgement-carrying packages. A shortfall fails the job rather than printing a warning.
  • database — 42 tests against a real Postgres 16 service container, not a mock.
  • pipeline — 377 pytest tests with a 90% gate in pyproject.toml.
  • Also in check: a documentation and source-encoding check, and npm ci rather than npm install, so lockfile drift fails the build instead of passing quietly. npm audit: 0 vulnerabilities.

What the checks actually caught

  • Four shape changes that the type system and the artefact guards both accepted. Found only by comparing whole API responses against the published files: 37 drainage links lost the reason a path stops and gained a null destination — the client would have walked into a pit that does not exist; 215 pits lost an empty key, turning “the record says there is no pipe” into “a pit we do not carry”; 163 street labels lost their display name; 22 pits had their links reordered.
  • A server that built, started, exited zero and listened on nothing. Its entry guard tested for a filename ending in server.ts — true of the source, false of the dist/server.js that actually ships. Every test passed, because the tests import the app and never run that line. Only building and running it showed the defect.
  • 167 drainage pits described as surface inlets that the council record calls junctions. One sentence had been shown for all 895 pits. Nobody noticed, because a sentence that is right 77% of the time reads exactly like one that is always right. It surfaced when a drawing had to decide whether to draw water entering — a picture cannot be vague — and the classification is now a tested rule.
  • A source file that was invisible to every code search. A raw NUL byte inside a string made git and grep treat the whole file as binary and skip it silently. It is now refused by a CI check that was watched failing on the real defect before it was trusted.
  • The promise that no address leaves the browser is enforced by a test, not by reading the code. It replaces both storages, history and document.cookie with traps, plays a whole session, and asserts nothing was written — then proves the traps work by writing to one on purpose.

Definition of done — what must pass before a user story closes

Acceptance criteria met · TypeScript build clean · both suites green with coverage thresholds enforced · documentation and encoding check passing · merged through a reviewed pull request · and, for anything a visitor can see, verified in a real browser and recorded in the deployment log — because a green suite says the code is right and says nothing about which build is serving.

What is not green

  • The suite-runtime gate cannot be passed or failed, because it never said which clock it means. Three runs of the same command: the test runner reported 3.74 s, 3.69 s and 5.12 s; the wall clock for those same three commands was 6.42 s, 6.42 s and 8.10 s. Both are honest measurements of different things. Recorded as a gate needing restatement rather than settled by choosing the flattering number.
  • The mobile layout is an unticked definition-of-done item. Measured rather than left as a checkbox: at 375 pixels the map legend covers more than half the map and the layer controls take two rows above it.
  • One colour token fails accessibility. The palette's quietest grey measures 3.34:1 against white where normal text needs 4.5:1, across about 25 strings — including the licence attribution the product is required to display. Fixing it changes how the whole product looks, so it is a design decision on the board rather than a silent edit.
